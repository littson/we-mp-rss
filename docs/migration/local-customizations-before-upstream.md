## 3. 对外 API 改动

### 3.1 公众号列表

接口：`GET /api/v1/wx/mps`

本地行为：

- 默认 `limit` 从 10 调整为 1000，最大值为 10000。
- 支持 `kw` 按公众号名称模糊查询。
- 列表项增加：
  - `frequency`
  - `recent_update_time`
  - `recent_update_time_text`
  - `rss_url`
  - `updated_at`
- 兼容旧频率值 `high`、`low`、空值，展示为 `daily`。

迁移要求：

- 保留模糊查询和上述外部字段。
- 使用上游当前 Feed schema、分页响应和认证依赖重新实现。
- 不覆盖上游已有字段。

### 3.2 搜索公众号

接口：`GET /api/v1/wx/mps/search/{kw}`

本地行为：

- 每个搜索结果增加 `subscribe_payload`。
- `subscribe_payload` 统一输出：
  - `mp_name`
  - `mp_id`
  - `avatar`
  - `mp_cover`
  - `mp_intro`

迁移要求：

- 如果上游已有等价添加流程，以其请求结构为准。
- 外部调用方仍需能够把搜索结果直接传入确认订阅接口。

### 3.3 确认订阅

接口：`POST /api/v1/wx/mps/confirm`

请求模型：`MpConfirmRequest`

本地行为：

- Base64 解码微信 `fakeid`，生成 `MP_WXS_<id>`。
- 按 `faker_id` 或内部 ID 检测重复订阅。
- 已存在时更新名称、头像和简介。
- 新订阅默认 `frequency=daily`。
- 本地保存头像。
- 同步所有消息任务中的公众号清单。
- 重载调度任务。
- 新订阅进入首次抓取队列。
- 响应增加 `created` 和 `message_task_updated`。

迁移要求：

- 复用上游订阅创建、队列、头像与数据库事务实现。
- 保留幂等确认语义和消息任务同步。
- 避免重复触发多页抓取；遵循上游当前限流策略。

### 3.4 删除订阅

接口：`DELETE /api/v1/wx/mps/{id}`

本地行为：

- 删除后同步全部消息任务的公众号清单。
- 重载调度任务。
- 清理对应 RSS 缓存。
- 响应返回删除 ID 和 `message_task_updated`。

迁移要求：

- 保留数据一致性行为。
- 使用上游现有级联、标签、缓存和关联删除机制。

### 3.5 二维码 Base64

接口：`GET /api/v1/wx/auth/qr/base64`

本地行为：

- Selenium 截取登录二维码并返回 Base64 PNG。
- 登录流程运行期间复用缓存二维码。
- 后台线程等待扫码，完成后更新 cookie/token。
- 原实现使用硬编码 `X-Auth-Token`。

迁移决策：

- 不移植硬编码令牌。
- 优先采用上游当前二维码接口和 Playwright 登录实现。
- 只有外部系统仍依赖 Base64 时，才新增受标准 JWT/AK 保护的兼容接口。

### 3.6 二维码最后登录时间

接口：`GET /api/v1/wx/auth/qr/last-login`

本地行为：

- 登录成功时记录 `wx_qr_last_login_time`。
- 返回 Unix 时间戳及本地 ISO 时间。

迁移要求：

- 上游若已有授权有效期或登录状态字段，优先映射到现有结构。
- 保留该兼容接口或等价响应。

### 3.7 RSS 接口

本地行为：

- `POST /rss/{feed_id}/api` 支持：
  - `original_link`
  - `cache_content`
- RSS 条目默认可直接指向微信原文。
- 仅在需要内部阅读页时缓存正文。
- RSS 输出增加全文字段。

迁移要求：

- 上游已支持 `rss.full_context`、RSS/Atom/JSON Feed，采用上游生成器。
- 验证 `content:encoded` 命名空间合法，正文不是被转义后的 HTML 文本。
- 保持微信原文链接选项和内部阅读链接兼容。

## 4. 内部业务逻辑改动

### 4.1 自适应抓取频率

本地新增 Feed 字段：

- `frequency`
- `consecutive_failures`
- `last_success_sync_time`

频率档位：

| 档位 | 调度 |
| --- | --- |
| `twice_daily` | 每天 06:00、23:00 |
| `daily` | 每天 23:00 |
| `three_day` | 每 3 天 23:00 |

统计规则：

- 统计窗口 28 天。
- 至少观察 14 天。
- 至少 3 篇文章。
- 连续失败或长时间无成功记录时跳过自动分档。
- 日均文章数 `>= 1.5`：`twice_daily`。
- 活跃日比例 `>= 0.65` 或日均文章数 `>= 0.8`：`daily`。
- 其他：`three_day`。
- 每 14 天 03:00 重新统计一次。

迁移要求：

- 保留上述业务口径，适配上游新的任务队列和 Feed 模型。
- 如果上游已有 `interval`、失败统计或环境异常字段，避免重复字段。
- 数据库迁移必须幂等，并兼容 SQLite/MySQL。

### 4.2 抓取成功与失败状态

本地行为：

- 成功时清零 `consecutive_failures` 并更新 `last_success_sync_time`。
- 失败时累计 `consecutive_failures`。
- 单个公众号失败不终止整个批次。
- 每个公众号单独计算本轮新增文章数量。

迁移要求：

- 对接上游当前任务历史、环境异常和队列记录。
- 不重复计算或覆盖上游更细的失败状态。

### 4.3 消息任务一致性

本地行为：

- 新增、更新、删除消息任务后立即重载调度器。
- 新增或删除公众号后，把全部订阅源同步到所有消息任务。
- `get_message_task_by_id()` 让调度器按任务 ID 重新读取最新配置。

迁移要求：

- 上游若已修复空 `mps_id` 或支持“全部公众号”，使用上游语义。
- 保留配置变更后无需重启进程即可生效。

### 4.4 队列空转修复

本地行为：

- 原队列在空队列时持续 `continue`，造成 CPU 空转。
- 修改为 `queue.get(timeout=1)`，捕获 `queue.Empty`。
- 停止标志在阻塞读取前检查。

迁移要求：

- 上游队列已重构，验证其为空时阻塞等待，不再移植旧实现。

### 4.5 调度器扩展

本地行为：

- 增加 `add_interval_job()`。
- Cron 和 Interval 均固定 `Asia/Shanghai`。
- 支持指定 `job_id`、删除和重新注册任务。

迁移要求：

- 复用上游调度封装；只补缺失能力。

### 4.6 数据库和会话

本地行为：

- SQLAlchemy Session 改为 `scoped_session`，线程隔离。
- SQLite 相对路径没有父目录时不再调用空路径 `makedirs`。
- 启动时幂等补充 Feed 自适应调度字段。
- 旧 `high`、`low` 和空频率迁移为 `daily`。
- 新增文章后清理对应 RSS 缓存。

迁移要求：

- 上游 schema 已大幅扩展，禁止沿用旧的启动时裸 `ALTER TABLE`。
- 使用上游迁移/兼容机制增加仍缺失的字段。
- 验证现有生产 MySQL 数据可以原位升级，不在本地修改生产数据。

### 4.7 RSS 缓存失效

本地行为：

- 新增 `RSS.invalidate(feed_id)`。
- 新文章写入后删除对应公众号及聚合 RSS 缓存。
- 删除订阅时清理对应缓存。

迁移要求：

- 使用上游 Redis/文件缓存抽象。
- 验证新增文章后下一次 RSS 请求可见新条目。

### 4.8 全文 RSS

本地行为：

- 注册 RSS Content Module：
  `http://purl.org/rss/1.0/modules/content/`
- 每个条目输出 `content:encoded`。
- `description` 保持摘要用途。

迁移决策：

- 上游已经支持 `rss.full_context=True`，不重复实现旧生成器。
- 增加回归测试验证 namespace、HTML、description 与全文同时存在。

### 4.9 微信图片文章解析（未提交）

新增：`core/wx/content.py`

入口：`parse_article_content(text)`

标准文章行为：

- 提取 `#js_content`。
- 删除容器隐藏样式。
- 把 `img[data-src]` 转为 `src`。
- 把图片固定像素宽度调整为 1080px。

图片文章行为：

- 当页面没有 `#js_content` 时解析 `window.picture_page_info_list`。
- 只提取图片对象顶层的 `cdn_url`。
- 排除 `watermark_info`、`share_cover` 中的辅助图片。
- 解析宽高。
- 解析 `window.desc`，解码 `\xNN`、`\uNNNN` 和 HTML entity。
- 协议相对 URL 和 `http://mmbiz.qpic.cn` 统一为 HTTPS。
- 去重并输出兼容的 `#js_content` 容器。

迁移要求：

- 上游浏览器模式可能从渲染后 DOM 获取图片，但 API/纯 HTTP 模式仍需静态回退。
- 将解析器接入上游统一正文抓取流程，而不是旧的 `wx.py/wx1.py/wx2.py`。
- 保留四个解析回归测试。
- 使用实际样例：
  `https://mp.weixin.qq.com/s/Pu_2AG0f6FFmKlBO_6otdA`

### 4.10 网络超时和资源释放

本地行为：

- 微信 API 默认超时 `(5, 30)`。
- 头像下载超时 `(5, 30)`。
- HTTPX 图片代理使用上下文管理器和 30 秒超时。
- 避免 AsyncClient 未关闭。

迁移要求：

- 上游已有更完整的超时和进程终止机制，以其为准。
- 验证所有外部请求存在有限超时。

### 4.11 告警

本地行为：

- 公众号抓取失败时调用自建推送接口。
- 超时 2 秒，记录响应并捕获错误。

迁移决策：

- 不移植源码中的硬编码签名和地址。
- 使用上游通知渠道或环境变量配置。
- 保留“单源失败通知但批次继续”的行为。

### 4.12 运行和日志

本地行为：

- 关闭 Uvicorn `reload`，避免生产环境文件变化触发重启。
- access log 增加时间。
- 增加 `run.sh`、`start_pm2.sh`。
- PM2 实际运行参数：
  `main.py -job True`，虚拟环境解释器启动。

迁移要求：

- 保留生产环境不启用 reload。
- PM2/systemd 属于服务器部署配置，不写死个人绝对路径到通用脚本。
- 上游启动参数、配置结构变化后更新部署说明。

## 8. 停止条件

迁移过程中出现以下情况必须停止并保留 checkpoint：

- 需要不可逆修改生产数据库。
- 必须删除上游公共接口才能恢复本地行为。
- 本地配置无法无损映射到上游配置。
- 后端关键测试失败率超过 5%。
- 图片文章实际样例无法复现或解析结果缺图。
- 前端构建失败且原因不是依赖安装问题。
